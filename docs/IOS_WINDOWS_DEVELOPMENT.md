# IOS Windows Development

> Canonical Windows-first developer workflow for the Harbor-iOS project.
> **The developer never touches a Mac.** All Apple-toolchain work runs behind automated CI in the cloud.

## 1. Hardware reality

- Development machine: Windows 11 PC.
- No local macOS, no local Xcode, no local iOS Simulator. This is a **design constraint, not a workaround**.
- Apple build infrastructure (Xcode, signing-capable tooling) is reached **only through GitHub Actions** on `macos-15` runners.

## 2. Windows prerequisites

| Tool | Version | Purpose |
|---|---|---|
| Git | any recent | source control |
| Node.js | LTS | repo tooling, script automation (optional for iOS-only work) |
| pnpm | 11.x | only if JS tooling is needed (Harbor reference analysis) |
| Rust + Cargo | stable | only for the portable core if/when we port `harbor-core` logic |
| Python | 3.11+ | structural verification scripts, IPA inspection, forensic tooling |
| GitHub account | — | repo hosting + Actions runs |

Install notes: use winget or official installers. `git-bash` (MSYS) is the shell used by this agent on Windows.

## 3. Environment variables

| Variable | Purpose | Notes |
|---|---|---|
| `GH_TOKEN` (optional) | `gh` CLI auth for workflow status | never put in source |
| `STREMIO_*`, `DEBRID_*` | **forbidden in repo** | live API keys live on-device only, entered by the user in-app |
| Apple ID | **never handled by the agent** | user enters it into AltStore/Sideloadly themselves |

## 4. Project setup

```bash
git clone https://github.com/HLYL0/Harbor-iOS.git
cd Harbor-iOS
# nothing to install locally: Swift sources are authored with any editor,
# the project is generated by XcodeGen on CI.
```

Local verification scripts (Windows-runnable):

```bash
python -c "import yaml; yaml.safe_load(open('project.yml'))"                 # project.yml parses
python -c "import plistlib; plistlib.load(open('HarborIOS/Info.plist','rb'))" # Info.plist parses
python scripts/verify_project.py                                             # structural gate (see scripts/)
```

## 5. Local development loop

1. Edit Swift under `Core/`, `Data/`, `Domain/`, `Features/`, `HarborIOS/`.
2. Run the structural verifier (`scripts/verify_project.py`) — catches phantom references, missing bootstrap files, YAML/Plist syntax.
3. Commit + push. CI (macos-15) runs: xcodegen generate → xcodebuild build → unit tests → IPA packaging → fake-sign (jailbroken path) → artifact.
4. Download artifact from Actions → hand to user for Filza/AltStore/Sideloadly install.
5. **Visual verification happens on the iPhone** — the agent cannot see the screen; the user reports what reads off.

## 6. Tests on Windows

- **Portable logic tests** (stream parser/trust/score/rank vectors, EPG/M3U parsing, subtitle parsing, URL validation, theme parsing): the canonical test vectors live as fixtures under `Tests/Fixtures/` and are exercised by (a) XCTest on CI and (b) a Windows-runnable Python reference runner where practical, so behavior is verified **before** spending a macOS run.
- **Swift-only tests**: run on CI (macos-15) as part of the build workflow. Windows can only verify structure, not compile Swift.

## 7. Lint / format

- Swift formatting is not enforceable on Windows; keep style consistent manually and let CI surface compiler-level issues.
- YAML/Plist: Python structural checks (see §4).
- If Rust code lands in the repo: `cargo fmt --check && cargo test` run on Windows locally.

## 8. CI

- `.github/workflows/build.yml` — macOS build/unit-test/package/fake-sign leg (see `IOS_BUILD_PIPELINE.md`).
- `.github/workflows/ci-windows.yml` — Windows leg: repo structural verification + any portable test runners (Python), so the agent catches broken pushes without consuming macOS minutes.

## 9. Secrets

- GitHub repo holds **no secrets**. No signing identities, no API keys, no Apple IDs.
- The IPA is unsigned (sideload) or fake-signed (jailbroken Filza path). See `IOS_BUILD_PIPELINE.md`.

## 10. Code signing workflow

- **Sideload path**: user's free Apple ID via AltStore/Sideloadly, entered by the user on their own PC. 7-day cert, re-signable over Wi-Fi.
- **Jailbroken path (LO's device)**: CI fake-signs with an `application-identifier` entitlement (any 10-char team ID; Dopamine's amfi patch accepts it), install via Filza.
- **TestFlight/App Store**: requires LO's paid Apple Developer credentials and a real distribution identity — out of scope for the agent; documented as the manual escalation path in `IOS_APPSTORE.md`.

## 11. Device testing workflow

1. Push → CI green → download `Harbor-iOS-unsigned-ipa.zip`.
2. LO extracts `HarborIOS.ipa`, installs via Filza (jailbroken) or AltStore.
3. LO reports behavior; agent fixes; repeat.
4. Every fix is verified against the **built artifact** (`scripts/inspect_built_ipa.py` on Windows can confirm Info.plist/content reached the bundle).

## 12. Hard limits (never pretend otherwise)

- No simulator, no Instruments, no Xcode debugger, no on-device automation from Windows.
- Compile errors only surface via CI logs → the extractor `scripts/extract_xcode_errors.py` buckets them.
- Never claim "works" for anything not proven by CI green + on-device confirmation.
